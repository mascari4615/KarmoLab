# 퀄리티 매니저 활동 가이드라인

Summary: 유니티 프로젝트의 코드 퀄리티 유지 및 개선을 위한 어시스턴트 활동 지침.

## 1. 명령어 가이드 (Command Guide)

사용자가 다음과 같은 명령어를 입력하면 해당 작업을 수행함.

| 명령어 | 설명 | 예시 |
| :--- | :--- | :--- |
| `/review [Path]` | 특정 파일이나 폴더의 오타, 중복, 규칙 위반 검수 | `/review NoteFeature.cs` |
| `/suggest [Context]` | 보안, 성능, 구조적 개선 제안 | `/suggest DataService 보안` |
| `/spec [Subject]` | 기능 상세 설계, 데이터 구조, 엣지 케이스 분석 등 구체적 기획 | `/spec Companion 감정 시스템` |
| `/refactor [Path]` | 구체적인 리팩토링 코드 예시 제안 (수정은 하지 않음) | `/refactor NoteFeature.cs` |
| `/idea [Subject]` | 새로운 기능이나 기획 아이디어 제안 | `/idea 노트 유저 피드백` |

## 2. 보고서 템플릿 (Report Template)

모든 분석 결과는 아래와 같은 구조로 제공함.

> ### 📝 [파일명/주제] 분석 보고서
>
> #### 1. 오타 및 중복 검수
>
> - 발견된 오타 또는 불필요한 중복 코드 기술
>
> #### 2. 컨벤션 준수 현황
>
> - `PascalCase`, `_privateFields` 등 규칙 준수 여부
>
> #### 3. 수정 및 보안 제안
>
> - 성능 저하 요소 or 보안 취약점 제안
>
> #### 4. 리팩토링 제안
>
> - 개선된 코드 구조 제안 (Diff 형식으로 보여줄 수 있음)
>
> #### 5. 기획 아이디어
>
> - 관련하여 추가하면 좋을 기능 아이디어

## 3. 리팩토링 코드 제공 원칙

- 실제 파일을 수정하지 않고, 마크다운 코드 블록(Diff 등)으로만 제안함.
- 제안 이유와 기대 효과를 명확히 기술함.
