# Companion Keyboard Feature Technical Detail (v2)

본 문서는 KarmoLab 컴패니언의 키보드 오버레이 및 입력 감지 기능의 통합 기술 구현 내역을 정리함.

---

## 1. 시스템 아키텍처 및 입력 파이프라인

KarmoLab 키보드 시스템은 안정성과 실시간성을 모두 확보하기 위해 **Win32 전역 후킹**과 **프로세스 격리형 파일 탐색기**를 혼합하여 사용함.

### 🧱 계층 구조

1. **Input Layer (Win32)**: `WH_KEYBOARD_LL`(Low-level) 후킹을 통해 시스템 전체의 키 이벤트를 가로챔.
2. **Buffer Layer (ConcurrentQueue)**: 후킹 콜백에서 발생하는 입력을 실시간으로 큐에 적재하여 유니티 메인 스레드와의 경합을 방지함.
3. **Processing Layer (Update)**: 유니티 루프 내에서 입력을 분석하고 조합키(Modifier) 상태를 판정함.
4. **UI Layer (UIToolkit)**: 분석된 데이터를 바탕으로 동적인 시각적 오버레이를 생성 및 렌더링함.

---

## 2. 주요 기술적 구현

### ⌨️ 전역 키보드 후킹 (`KeyboardModule.cs`)

- **수식키 판정**: `Shift`, `Ctrl`, `Alt`, `Win` 등 수식키가 눌린 상태에서 일반 키가 입력되면 조합(Combo) 모드로 진입.
- **조합 완성**: 수식키가 떼어지는(KeyUp) 시점에 조합을 하나의 행으로 히스토리에 기록.
- **특수 문자 매핑**: OEM 코드를 분석하여 `,`, `.`, `/`, `;` 등 기호와 `F1-F12` 키를 실제 문자로 변환.

### 📂 프로세스 격리형 파일 탐색기 (`Win32FileBrowser.cs`)

- **도입 배경**: `comdlg32.dll`을 직접 호출할 경우 유니티 엔진의 메모리 관리 및 메시지 루프와 충돌하여 하드 크래시를 유발함.
- **해결 방안**: **PowerShell**을 별도 프로세스로 실행하여 `System.Windows.Forms.OpenFileDialog`를 호출함.
- **장점**: 탐색기 창이 유니티와 완전히 다른 메모리 공간에서 동작하므로, 탐색기 사용 중에도 유니티의 후킹 및 애니메이션이 멈추지 않는 극도의 안정성을 제공함.

---

## 3. UI 및 시각적 효과

### 🎈 레이아웃 시스템

- **역방향 스택 (Bottom-up)**: 최신 입력 행이 오버레이의 가장 하단에 배치되며, 이전 행들은 위로 점진적으로 밀려 올라감.
- **조합키 오버레이**: 진행 중인 조합키(`Ctrl + Shift` 등)는 히스토리 행들과 분리되어 최상단에 별도로 표시됨.

### 🕯️ 독립적 페이드아웃

- 각 행(`RowData`)은 고유의 타임스탬프를 가져 생성 및 업데이트 시점으로부터 독립적으로 투명도가 조절됨.
- 활성 행이 히스토리로 전환될 때 시간 정보를 동기화하여 깜빡임 없이 부드러운 전환을 보장함.

## 4. 벤치마킹 및 고도화 방향

선행 레퍼런스([Carnac, NohBoard, Keyviz](file:///c:/Users/masca/source/repos/KarmoLab/Unity/KarmoLab/docs/keyboard_feature_benchmark.md)) 분석 결과, 다음과 같은 고도화가 계획됨:

- **애니메이션 정교화**: Keyviz 스타일의 부드러운 입출력 전환 애니메이션 적용.
- **최적화**: Carnac의 연속 입력 요약(Backspace x 5) 로직 도입 고려.
- **안정성**: 현재의 프로젝트 격리 전략을 더욱 견고히 하여 모든 런타임 환경에서 0-Crash 달성.
