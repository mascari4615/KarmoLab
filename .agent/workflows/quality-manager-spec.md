# 퀄리티 매니저 기획/분석 역량 가이드

Summary: `/spec` 명령어를 통한 기획 및 상세 설계 범위와 예시 정리.

## 1. 시스템 설계 (System Architecture)

단순한 기능 제안을 넘어, 실제 구현 가능한 수준의 클래스/데이터 구조를 설계함.

- **데이터 모델링**: JSON 저장 구조, `Serializable` 클래스 계층 구조 설계.
- **클래스 관계도**: `Manager`, `Controller`, `View` 간의 책임 분리 및 상호작용 설계 (Mermaid 다이어그램 활용).
- **디자인 패턴 적용**: 기능에 적합한 패턴(Singleton, Observer, Strategy 등) 추천 및 적용 예시.

> **예시**: "Companion 감정 시스템을 위한 `EmotionData` 클래스 구조와 `EmotionManager` 설계해줘."

## 2. UI/UX 설계를 위한 구조적 분석

화면의 흐름과 사용자 인터랙션을 구조적으로 설계함.

- **UI 계층 구조**: `VisualElement` 트리 구조 및 스타일링(USS) 가이드.
- **사용자 시나리오 (User Flow)**: 진입부터 목표 달성까지의 단계별 UX 흐름 정리.
- **인터랙션 피드백**: 클릭, 호버, 드래그 시의 시각/청각적 피드백 정의.

> **예시**: "대시보드에서 퀘스트 완료 시 나오는 폭죽 효과와 팝업 애니메이션 시퀀스 정리해줘."

## 3. 콘텐츠 및 밸런싱 (Content & Balancing)

데이터 기반의 기획 내용을 구체화함.

- **데이터 테이블 구조**: 아이템, 퀘스트, 업적 등의 데이터 테이블 필드 정의.
- **수치 밸런싱**: 레벨업 경험치 테이블, 재화 획득량 등 수치 시뮬레이션.

## 💡 활용 팁

`/spec` 요청 시 구체적인 **목표**나 **제약 사항**을 함께 알려주면 더 정교한 설계가 가능함.

- ❌ `/spec 퀘스트 시스템` (너무 포괄적)
- ⭕ `/spec 퀘스트 시스템 데이터 구조와 일일 초기화 로직` (구체적)
