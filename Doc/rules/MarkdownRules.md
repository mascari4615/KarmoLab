# Markdown Rules (KarmoLab Docs)

목적: markdownlint 회피 + 일관 스타일 유지 위한 최소 규칙.

## 필수 규칙

1. 한 문서당 `#` 헤딩은 한 번만 사용. 이후는 `##`, `###` 순차 증가.
2. 헤딩, 코드블럭 전후로 빈 줄 1줄.
3. 목록/문단 의미 전환 시 빈 줄 1줄.
4. 코드 블록 언어 태그 필수(예: ` ```bash`, ` ```csharp`, ` ```text`).
5. 테이블/코드/목록 끝 불필요 공백 금지.
6. 탭 대신 스페이스 사용(2~4칸 일관 유지).
7. 줄바꿈은 120자 이내 권장(긴 URL 제외).
8. 문체는 간결 우선. 가독성 해치지 않는 범위에서 음슴체 등 간략체 허용.
9. 시간 표기는 한국 표준시(KST) 기준으로 명시(예: `2025-12-09 10:05 KST`).

### 히스토리 규칙

1. 필수 규칙 준수.
2. 주요 변경/마일스톤만 기록(예: 환경 구축, 첫 빌드, 주요 기능 추가/변경).
3. 날짜: `YYYY-MM-DD (KST)` 헤더.
4. 필요 시 시간 `HH:MM` KST.
5. 사소한 수정/실험 생략, 핵심만 요약.

## 권장 패턴

- 디렉터리 트리: ` ```text` fence 사용.
- 명령어: ` ```bash` fence 사용.
- JSON/YAML 예제: ` ```json`, ` ```yaml`.
- C# 예제: ` ```csharp`.
- 번호 목록과 문단 사이에도 빈 줄을 넣어 가독성 확보.

## 문서 작성 체크리스트

- [ ] H1은 문서 제목 하나만 있는가?
- [ ] 모든 코드 블록에 언어 태그가 있는가?
- [ ] 헤딩/목록/문단 사이에 필요한 빈 줄이 있는가?
- [ ] 불필요한 공백(줄 끝, 두 칸 이상 연속 빈 줄)이 없는가?
- [ ] 디렉터리 트리/명령어에 적절한 fence 언어를 썼는가?

## 적용 대상

- `Doc/` 이하 모든 문서 작성/수정 시 준수
- 새 문서 생성 요청 시 본 규칙을 기본 템플릿으로 사용
