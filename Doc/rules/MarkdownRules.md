# Markdown Rules (KarmoLab Docs)

목적: markdownlint 기본 경고를 피하고, 일관된 문서 스타일을 유지하기 위한 최소 규칙.

## 필수 규칙

1. 한 문서당 `#` 헤딩은 한 번만 사용. 이후는 `##`, `###` 순차 증가.
2. 헤딩, 코드블럭 전후로 빈 줄 1줄씩 둡니다.
3. 목록/문단 사이에는 의미가 바뀌면 빈 줄 1줄을 둡니다.
4. 코드 블록에는 언어 표시를 붙입니다(예: ` ```bash`, ` ```csharp`, ` ```text`).
5. 테이블/코드 블록/목록 끝에는 불필요한 공백(trailing space)을 두지 않습니다.
6. 탭 대신 스페이스 사용(2~4칸 일관 유지).
7. 줄바꿈은 120자 이내 권장(긴 URL 제외).
8. 문체는 간결 우선. 가독성을 해치지 않는 범위에서 음슴체(서술어 생략체) 등 간략체 사용 허용.

## 권장 패턴

- 디렉터리 트리: ` ```text` fence 사용.
- 명령어: ` ```bash` fence 사용.
- JSON/YAML 예제: ` ```json`, ` ```yaml`.
- C# 예제: ` ```csharp`.
- 번호 목록과 문단 사이에도 빈 줄을 넣어 가독성 확보.

## 문서 작성 체크리스트

- [ ] H1은 문서 제목 하나만 있는가?
- [ ] 모든 코드 블록에 언어 태그가 있는가?
- [ ] 헤딩/목록/문단 사이에 필요한 빈 줄이 있는가?
- [ ] 불필요한 공백(줄 끝, 두 칸 이상 연속 빈 줄)이 없는가?
- [ ] 디렉터리 트리/명령어에 적절한 fence 언어를 썼는가?

## 적용 대상

- `Doc/` 이하 모든 문서 작성/수정 시 준수
- 새 문서 생성 요청 시 본 규칙을 기본 템플릿으로 사용
