# Config Management: .env vs. Environment Variables

Summary: KarmoLab 프로젝트에서 .env 대신 환경 변수와 User Secrets를 사용하는 기술적 배경과 장단점 분석.

## 1. 비교 분석 (Comparison)

| 특징 | .env 파일 | 환경 변수 (OS) | .NET User Secrets |
| :--- | :--- | :--- | :--- |
| **저장 위치** | 프로젝트 폴더 내 파일 | OS 시스템 메모리/레지스트리 | 사용자 프로필 폴더 (%APPDATA%) |
| **보안성** | 낮음 (Git 오커밋 위험) | 높음 (메모리 상주) | 매우 높음 (프로젝트와 물리적 분리) |
| **편의성** | 높음 (텍스트 수정) | 보통 (터미널/제어판 조작) | 보통 (CLI 도구 필요) |
| **이식성** | 높음 (파일 복사) | 매우 높음 (클라우드 표준) | 낮음 (로컬 머신 종속) |

## 2. 각 방식의 장단점

### ✅ 환경 변수 (Environment Variables)

- **장점**:
  - **플랫폼 불가지론**: Docker, K8s, Azure 등 모든 클라우드 인프라의 표준 설정 방식임.
  - **보안**: 파일이 아니므로 디스크에 흔적이 남지 않으며, 프로세스 실행 시에만 주입됨.
- **단점**:
  - 로컬에서 여러 개의 변수를 수동으로 설정하기 번거로울 수 있음.

### ✅ .NET User Secrets

- **장점**:
  - **안전한 분리**: 설정 데이터가 프로젝트 소스 트리 밖에 저장되어 Git에 실수로 포함될 일이 원천적으로 차단됨.
  - **협업**: 개발자 개별적으로 다른 API 키를 사용해야 할 때 유용함.
- **단점**:
  - 팀원 간 동기화가 자동으로 되지 않음 (명시적으로 공유 필요).

### ❌ .env (파일 방식) - KarmoLab 권장하지 않음

- **특징**: 간편하지만, `.gitignore` 설정 실수 한 번으로 API 키가 전 세계에 공개될 수 있는 리스크가 큼.
- **결론**: KarmoLab은 "보안 > 편의성" 원칙에 따라 이 방식을 폐기함.

## 3. 결론 및 권장 사항

1. **로컬 개발**: `.NET User Secrets`를 최우선으로 사용함 (`dotnet user-secrets`).
2. **서버/배포**: 인프라 수준의 **환경 변수**를 사용함.
3. **코드 구현**: 특정 파일 형식에 의존하지 않고 .NET의 `IConfiguration`이나 `Environment.GetEnvironmentVariable()`을 사용하여 추상화된 값만 가져오도록 설계함.
