# 유니티 패키지 시멘틱 버저닝(SemVer) 가이드

유니티 패키지 매니저(UPM)는 **Semantic Versioning(시멘틱 버저닝)** 표준을 따름. 버전 번호는 `MAJOR.MINOR.PATCH` 형식.

## 1. 버전 번호의 의미

### [MAJOR] . Minor . Patch
- **언제 올리나요?**: 기존 기능을 삭제하거나, API를 크게 수정하여 **이전 버전과 호환되지 않을 때(Breaking Changes)** 올림.
- **예시**: 프로젝트 구조를 완전히 갈아엎거나, 필수 함수 이름을 바꿨을 때.

### Major . [MINOR] . Patch
- **언제 올리나요?**: 새로운 기능을 추가했지만, **기존 기능도 문제없이 잘 돌아갈 때(Backwards Compatible)** 올림.
- **예시**: 새로운 툴바 메뉴 추가, 새로운 유틸리티 클래스 추가.

### Major . Minor . [PATCH]
- **언제 올리나요?**: 새로운 기능 없이 **버그 수정이나 내부 성능 개선**만 했을 때 올림.
- **예시**: 오타 수정, 에러 문구 수정, 최적화.

## 2. 배포 흐름 예시

1. **v1.0.0**: 첫 정식 배포!
2. **v1.0.1**: 툴바 오타 수정. (Patch)
3. **v1.1.0**: 툴바에 새로운 씬 선택 모드 추가. (Minor)
4. **v1.1.1**: 새로운 모드 버그 수정. (Patch)
5. **v2.0.0**: 툴바 시스템 전면 개편으로 기존 설정과 호환 불가. (Major)

## 3. 주의사항 및 팁

- **package.json과 일치**: 꼭 `package.json` 파일 안의 `"version"` 값과 Git Tag의 버전 번호 일치해야 함. (다르면 유니티가 혼란스러워 함)
- **0.x.y 버전**: 개발 초기 단계(Pre-release)에서는 `0.1.0`, `0.2.0` 처럼 시작해도 좋음. 이 버전 대에서는 언제든 기능이 바뀔 수 있다는 암묵적인 약속이 있음.
- **수정 후 덮어쓰기 금지**: 이미 배포한 `v1.0.0` 태그의 내용을 몰래 바꾸는 것보다는, `v1.0.1`로 올려서 정식 배포하는 것이 사용자의 패키지 업데이트를 유도하기 좋음.

## 4. 유니티 프리뷰(Preview) 태그

아직 정식 버전은 아니지만 테스트가 필요할 때 버전 뒤에 붙음.
- `1.0.0-preview.1`
- `1.0.0-alpha`
- `1.0.0-rc.1` (Release Candidate)
