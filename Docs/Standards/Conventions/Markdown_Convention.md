# Markdown 작성 규칙

KarmoLab 내 모든 문서(.md) 작성 시 지켜야 할 스타일 가이드.  
Readme.md 파일은 예외.

## 1. 포맷팅 규칙
- **헤딩**: 문서 제목은 `#` 하나만 사용, 이후 `##`, `###` 순으로 계층 구성.
- **코드 블록**: 언어 태그 반드시 명시. (예: ` ```csharp`, ` ```bash`)
    - C#: ` ```csharp`
    - Shell: ` ```bash` 또는 ` ```powershell`
    - JSON: ` ```json`
- **들여쓰기**: 탭을 일관되게 사용. (들여쓰기 X)

## 2. GitHub Flavored Markdown (GFM) 활용

### 2.1. 체크리스트 (Task Lists)
- [ ] 할 일 (미완료)
- [x] 완료된 일

### 2.2. 테이블 (Tables)
데이터 나열이 필요할 때는 표 사용.

| 항목 | 설명 | 비고 |
| :--- | :--- | :--- |
| Item | Description | Note |

### 2.3. 취소선 (Strikethrough)
- 취소된 내용이나 변경된 사항은 `~~취소선~~` 사용해 ~~이렇게~~ 표시.

### 2.4. 알림 (Alerts)
- 중요하거나 주의해야 할 내용은 GitHub Alerts 문법 사용.
> [!NOTE]
> 참고 사항.

> [!WARNING]
> 주의 사항.

## 3. 언어 및 스타일
- **언어**: 기본적으로 **한국어** 사용.
- **어조**: 간결하고 명확하게 작성. 음슴체 사용 권장.
- **시간 표기**: 날짜 등 시간이 필요할 경우 **KST(한국 표준시)** 기준으로 명시. (예: `2026-01-17 (KST)`)

## 4. 문서 작성 후 점검

- 문서 제목 H1(`#`) 하나만 존재하는가?
- 코드 블록 언어 태그 빠짐없이 붙어있는가?
- 문단 사이 적절한 빈 줄 있어 가독성이 좋은가?
