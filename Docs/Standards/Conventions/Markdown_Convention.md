# Markdown 작성 규칙

Summary: KarmoLab 내 모든 문서(.md) 작성 시 지켜야 할 스타일 가이드.
Readme.md 파일은 예외.

## 0. 문서 구조

- **문서 제목(H1)**: 파일 최상단에 하나만 존재해야 함.
- **Summary**: 문서 제목(#) 바로 다음 줄 또는 다음 빈 줄 뒤에 문서의 목적을 한 줄로 요약함. (마크다운 가이드 MD041 준수를 위해 제목보다 먼저 적지 않음)

## 1. 포맷팅 규칙

- '표준 마크다운 포맷팅' (GitHub Flavored Markdown) 준수.
- **헤딩**: 문서 제목은 `#` 하나만 사용, 이후 `##`, `###` 순으로 계층 구성.
  - **모든 헤딩 뒤에는 반드시 한 줄의 빈 줄을 삽입함.** (가독성 확보)
- **코드 블록**: 언어 태그 반드시 명시. (예: ` ```csharp`, ` ```bash`)
  - C#: ` ```csharp`
  - Shell: ` ```bash` 또는 ` ```powershell`
  - JSON: ` ```json`
- **들여쓰기**: 탭을 일관되게 사용. (들여쓰기 X)
- **구분선**: `---` 같은 수평선 사용하지 않음.

### 1.1. 체크리스트 (Task Lists)

- [ ] 할 일 (미완료)
- [x] 완료된 일

### 1.2. 테이블 (Tables)

데이터 나열이 필요할 때는 표 사용.

| 항목 | 설명 | 비고 |
| :--- | :--- | :--- |
| Item | Description | Note |

### 1.3. 취소선 (Strikethrough)

- 취소된 내용이나 변경된 사항은 `~~취소선~~` 사용해 ~~이렇게~~ 표시.

### 1.4. 알림 (Alerts)

- 중요하거나 주의해야 할 내용은 GitHub Alerts 문법 사용.

> [!NOTE]
> 참고 사항.

`[!TIP]`, `[!IMPORTANT]`, `[!WARNING]` 등도 사용.

### 1.5. 푸터 및 서명 (Footer & Signature)

- 문서 하단에 작성자, 관리 주체 등을 명시할 때는 **인용문(`>`)** 형식을 사용함.
- 이는 헤딩으로 오해받는 것(MD036)을 방지하고 일반 본문과 시각적으로 분리하기 위함임.
- 예: `> **관리 주체**: Alisa (PM)`

## 2. 언어 및 스타일

- **언어**: 기본적으로 **한국어** 사용.
- **어조**: 간결하고 명확하게 작성. 음슴체 사용 권장.
- **시간 표기**: 날짜 등 시간이 필요할 경우 **KST(한국 표준시)** 기준으로 명시. (예: `2026-01-17 (KST)`)

## 3. 문서 작성 후 점검

- 표준 마크다운 포맷팅 준수하는가?
- 문서 제목 H1(`#`) 하나만 존재하는가?
- 코드 블록 언어 태그 빠짐없이 붙어있는가?
- 문단 사이 및 **헤딩 뒤에** 적절한 빈 줄이 있어 가독성이 좋은가?
