# YawnBot 히스토리 (History)

Summary: YawnBot 프로젝트의 주요 업데이트 기록 및 마일스톤.

## 2026-01-18 (KST)

### 🏗️ .NET 표준 구조 리팩토링 및 배포 개선

- **프로젝트 구조 표준화 (`src/` 도입)**
  - 기존의 평면적인 구조에서 벗어나, 소스 코드를 `src/YawnBot` 하위로 이동하여 표준 .NET 솔루션 구조 확립함.
  - `.sln` 파일을 루트에 배치하여 IDE 호환성 및 빌드 편의성 높임.

- **배포 및 운영 자동화 (`deploy.ps1` V2)**
  - `src` 디렉토리 빌드 지원 및 `.env` 파일 자동 우회 처리 추가함.
  - 배포 후 자동으로 로그를 모니터링(`watch_logs.ps1`)하도록 스크립트를 연결하여, 배포 즉시 서버 상태 확인 가능해짐.
  - `watch_logs.ps1`: SSH를 통해 실시간으로 서버 로그(`journalctl -f`)를 스트리밍하는 스크립트 추가함.

### 🩹 데이터 복구 및 정비 (Data Recovery)

- **무기 데이터 사고 복구 (Lore Restoration)**
  - JSON 필드 정리(`prompt` 제거 등) 작업 중 실수로 소실되었던 모든 무기(12종)의 "Lore(설명)" 데이터 복구함.
  - **Git History Hash Recovery**: 단순 파일 복구가 아닌, Git 히스토리의 특정 커밋(`de4086d`) Blob Hash를 추적하여 바이너리 레벨에서 원본 데이터 정밀 추출함.
  - 복구와 동시에 불필요한 필드(`prompt`, `visualDescription`, `createdAt`)를 제거하여 데이터 경량화도 함께 완료함.

- **`Etc` 폴더 정비**
  - 존재하지 않던 `Etc_data.json`으로 인한 잠재적 오류를 방지하기 위해, 표준 규격(`stages: []`)을 준수하는 빈 데이터 파일을 생성하여 정합성 맞춤.

## 2026-01-17 (KST)

### 🛠️ 리팩토링 & 메시지 시스템 개편 (Refactoring)

- **Enum 기반 메시지 키 도입 (`BotMessageKey`)**
  - 기존의 하드코딩된 문자열을 모두 제거하고, `BotMessageKey` Enum을 사용하여 컴파일 타임에 키 유효성을 검증하도록 변경함.
  - 오타로 인한 런타임 에러 방지 및 유지보수성 향상.

- **메시지 중앙화 (`bot_messages.json`)**
  - 봇에서 사용하는 모든 메시지를 `Data/bot_messages.json` 파일로 추출하여 통합 관리함.
  - 추후 다국어 지원(Localization) 및 메시지 문구 수정이 용이해짐.

- **서비스 구조 개선 및 안정화**
  - `GameDataService`: 메시지 로드 및 제공 역할 강화, Enum 키 기반 조회 메서드(`GetMessage`) 구현.
  - 모든 서비스(`Enhancement`, `Raid`, `Stock` 등) 및 모듈(`General`, `Admin` 등)이 `GameDataService`를 통해 메시지를 가져오도록 통일.
  - 엄격한 타입 규칙(`var` 지양) 적용 및 빌드 오류 해결.

### ⚔️ 레이드 (Raid) 시스템 [진행 중]

- **개요:** 모든 유저가 협력하여 강력한 보스 몬스터 처치.
- **방식:**
  - 관리자 또는 일정 시간마다 보스 소환.

- **보상:** 골드, 특수 칭호, 강화 보호권 등.
